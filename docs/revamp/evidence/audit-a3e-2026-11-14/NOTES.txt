How measured
- Real stylesheets: production build (pnpm build, next start), signed in as the seeded QA test customer (scripts/qa/signed-in-sweep.ts --serve, local PostgreSQL 16),
  Chromium. Every details element closed. Screens = full document height (header, content, footer) divided by the viewport height:
  390x844, 768x1024, 1440x900. 1.000 means the page is not taller than the window and the footer sits at the bottom of it.
- before = origin/main 76066ca (PR 502 merged). after = this branch, built from its final code (merged with main before the push).
- State "3 rows" (the seeded customer, the same state A3a measured as home-filled): Home shows exactly 3 work rows and no stage bar:
  1. "Synthetic QA Test open request" (Draft request)   2. "Local meeting arrangement" (Service request)   3. "Synthetic QA Test buyer delegation" (Programme).
  The seed has no submitted request, so the "Newest request" stage bar is absent. Next step row, Active work, See all your work, 4 quick links.

All Tools without JavaScript (tests/ux/audit-a3e-all-tools-no-js.spec.ts, 30 tests: 10 at each of 390, 768, 1440)
- Browser context javaScriptEnabled false. The page route is served by a fixture: the REAL AllToolsFinder, WorkspaceShell and stylesheets rendered on the server per request
  from the address, answering /account/all-tools. Its two reads of the address copy app/account/all-tools/page.tsx.
- Proves: the server markup for ?q= and ?group= filters correctly; the form in it (field names q and group, action, the noscript Find button, the radio chips, Clear Search)
  makes a real GET in Chromium that lands on the filtered or the cleared page; all 16 tools are on the page with no query; a word with no match says so and Clear Search
  brings all 16 back; each tool is found by its own label.
- Does NOT prove: the Next page itself, its sign-in, CORRIDRA_UX_NAV, or that page.tsx passes searchParams (that last part is read in tests/integration/audit-a3a-screens.test.ts).
- New in the finder: Clear Search was a JavaScript-only button, so without a script a search could not be cleared. It is now a submit button in a small GET form to
  /account/all-tools; with a script its click handler still clears in place (button role and label unchanged).
- Fails when the GET path is broken (temporary local breaks, all restored; run at 1440):
  A origin/main finder (Clear is JS-only): 6 failures across the 3 widths (Clear Search tests, 2 per width)
  B name="q" removed from the search box: 2 failures (Find loads ?q=, Find loads ?group=)
  C address not read (initialQuery and initialGroup ignored): 7 failures
  D noscript Find button removed: 3 failures
