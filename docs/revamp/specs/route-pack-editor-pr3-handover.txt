## What PR3a is

- POST `route-pack-publish` with `{ mode: 'preview' | 'publish', change }`. `change` is kind `settings` (key lists, `manualChannel`, `removeSourcingProfile`) or kind `status`.
- It answers 404, the same as an unknown action, while `CORRIDRA_ROUTE_PACK_FORM` is off or the 2b marker is absent. The 2b marker is absent in production today.
- The first service call is `proposalOf` (`config.manage`), so other roles get 403 before any state is read.
- Answers carry no ids and no reasons.
- Code: `packages/missions/src/route-pack-form.ts` (`routePackChangeRequest`, `previewRoutePackChange`, `publishRoutePackChange`), `apps/web/lib/route-pack-editor-publish.ts`, `apps/web/app/api/team-control/[action]/route.ts`, `tests/integration/route-pack-editor-publish.test.ts`.

## Known limit (accepted for now, G71 to decide)

After a publish, the same command id with a list left out, or with `removeSourcingProfile` on a base pack that had no sourcing block, still answers 200 duplicate. Nothing is written twice. Closing it needs a read of a past pack's configuration by id. That read would be added to `route-pack-content.ts`, outside the PR3a files.
