# Lane 7b: Pulse notification records

Status: built and dark, 24 October 2026. Switch `CORRIDRA_PULSE_ENABLED` (off by default) and a database control that starts closed. Decision record: [ADR-067](../adr/0067-notification-records-and-pulse.md). Owner steps and open decisions: [phase2-install.md](phase2-install.md).

## What exists

| Part                   | What it does                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Database module        | `customer_notification_migrations/0001_notifications.sql`: a closed-by-default control, per-person preferences (append only, newest wins), per-request mutes (append only), an outbox (ids, a plain title, a date, never an address), and the functions that queue, seal, claim, finish and mute. Additive; mission mail is neither read nor written.                            |
| Queueing               | `customer.enqueue_move_notifications(command)` runs inside the Corridra team's own transaction after Moves are set. It reads only facts the database already holds (the Moves of that one command that the customer holds and that are still open) and refuses anyone who is not a team member acting on their own command. Caps: three a day per request, ten a day per person. |
| Sealing                | The application seals each queued message once with digests of two secrets only it can compute (the send capability and the mute token). An unsealed message cannot be claimed and expires.                                                                                                                                                                                      |
| Sending                | `PulseService.send`: claim, resolve the address through the address port, render, send once (idempotent key), finish. Three attempts, a 60 second lease, valid for 24 hours from when it can first be sent. A message about a Move that is done, cleared, muted or switched off by the person is suppressed, never sent.                                                         |
| Digest and quiet hours | In the person's own time zone, in the database: a digest waits for the next 08:00 local; quiet hours push a time inside them to the end of the window. Both only delay. A digest leaves as one email holding everything due for that person.                                                                                                                                     |
| Templates              | `packages/auth/src/pulse-templates.ts`: One thing needs you, Your request moved forward, A date is coming up, Your mission is complete, and the daily digest. Titles and dates only, escaped, plain-text twin, single column, no tracking pixel. Mission mail's templates are not edited.                                                                                        |
| Email choices page     | `/account/notifications` (More, and All tools): which messages, one email a day, quiet hours, time zone, language. Saves append a new version. 404 with the switch off.                                                                                                                                                                                                          |
| Mute page              | `/pulse/mute/[requestId]`: opening the link does nothing; the button mutes one request once. It keeps working if the switch is turned off.                                                                                                                                                                                                                                       |
| Sign-in return         | `accountReturnTo` keeps an exact short list of email pages while Pulse is on. Off, it keeps `/plan` only, as before.                                                                                                                                                                                                                                                             |
| Staff route            | `/api/move/staff` queues email after a new Move set is stored. A mail problem never fails or undoes the Move. Nothing starts without an address source.                                                                                                                                                                                                                          |

## What is not built, and why

- Emitters for messages 5, 6 and complete (a request moved forward, a date is near, a mission closed). The queue, the database kinds and the templates exist; the triggers wait for the interview results in [phase2-interviews.md](phase2-interviews.md), which decide whether these are worth switching on.
- An address source (see phase2-install.md): that is a privacy decision.
- Web push and WhatsApp: outside ADR-067.

## Verification

- Database suite `notification-database.test.ts` (38 tests): additive upgrade; idempotent install that refuses a changed history; closed control; roles cannot touch the tables; timing across time zones and both daylight saving changes; preferences append only with every invalid choice refused; only a team member acting on their own command queues; seal once; caps; mute once for one request; stale Move suppressed; retries and expiry; digest in one email; the application service end to end with a recorded sender.
- Unit suite `ux-pulse.test.ts` (67 tests): choices, every template, mute token purpose, the sign-in allow-list refusing 24 shapes, every switch-off path, no address column in the module.
- Operator spec `ux-pulse.spec.ts` (12 tests): the real Email choices screen and mute page with the real stylesheets, 320 to 1440 px, 44 px targets, no sideways scroll, clean accessibility scan. Screenshots in `docs/design-system/evidence/lane7b-pulse/`.
