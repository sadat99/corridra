## What exists

| Part                   | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Database module        | `customer_notification_migrations/0001_notifications.sql` and `0002_email_off_until_chosen.sql` (email off until a person switches it on; the send-time address lookup): a closed-by-default control, per-person preferences (append only, newest wins), per-request mutes (append only), an outbox (ids, a plain title, a date, never an address), and the functions that queue, seal, claim, finish and mute. Additive; mission mail is neither read nor written. |
| Queueing               | `customer.enqueue_move_notifications(command)` runs inside the Corridra team's own transaction after Moves are set. It reads only facts the database already holds (the Moves of that one command that the customer holds and that are still open) and refuses anyone who is not a team member acting on their own command. Caps: three a day per request, ten a day per person.                                                                                    |
| Sealing                | The application seals each queued message once with digests of two secrets only it can compute (the send capability and the mute token). An unsealed message cannot be claimed and expires.                                                                                                                                                                                                                                                                         |
| Sending                | `PulseService.send`: claim (one claim at a time for one person, so two messages due together become one digest email, never two), resolve the address through the address port, render, send once (idempotent key), finish. Three attempts, a 60 second lease, valid for 24 hours from when it can first be sent. A message about a Move that is done, cleared, muted or switched off by the person is suppressed, never sent.                                      |
| Digest and quiet hours | In the person's own time zone, in the database: a digest waits for the next 08:00 local; quiet hours push a time inside them to the end of the window. Both only delay. A digest leaves as one email holding everything due for that person.                                                                                                                                                                                                                        |
| Templates              | `packages/auth/src/pulse-templates.ts`: One thing needs you, Your request moved forward, A date is coming up, Your mission is complete, and the daily digest. The name on the account, the team's short Move description (80 characters at most) and a date; a subject never carries the team's words. Escaped, plain-text twin, single column, no tracking pixel. Mission mail's templates are not edited.                                                         |
| Email choices page     | `/account/notifications` (More, and All tools): which messages, one email a day, quiet hours, time zone, language. Saves append a new version. 404 with the switch off.                                                                                                                                                                                                                                                                                             |
| Mute page              | `/pulse/mute/[requestId]`: opening the link does nothing; the button mutes one request once. It keeps working if the switch is turned off.                                                                                                                                                                                                                                                                                                                          |
| Sign-in return         | `accountReturnTo` keeps an exact short list of email pages while Pulse is on. Off, it keeps `/plan` only, as before.                                                                                                                                                                                                                                                                                                                                                |
| Staff route            | `/api/move/staff` queues email after a new Move set is stored. A mail problem never fails or undoes the Move. Nothing starts unless the switch, real use and the control are all on, and only for people who switched email on.                                                                                                                                                                                                                                     |

## What is not built, and why

- Emitters for messages 5, 6 and complete (a request moved forward, a date is near, a mission closed). The queue, the database kinds and the templates exist; the triggers wait for the interview results in [phase2-interviews.md](phase2-interviews.md), which decide whether these are worth switching on.
- Nothing is sent until the owner has done the privacy review of the texts, opened the control and switched `CORRIDRA_PULSE_ENABLED` on. The address source is built (owner decision of 25 October 2026, ADR-067): the verified address is read from the sign-in provider at send time, only for a person who switched email on, and email is off for everyone until they do.
- Web push and WhatsApp: outside ADR-067.
