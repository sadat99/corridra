# Parallel work operating rules (owner, 13 November 2026)

Document status: CURRENT. Standing owner rules, recorded from the owner's message in the orchestrator session (`session_0187kU9uRvNguE7Dz4mt8zgM`, 13 November 2026, about 08:40 UTC). Summary and entry point: [AGENTS.md](../../AGENTS.md).

Standing owner rules for parallel Claude Code sessions, typed by the owner in the orchestrator session at about 08:40 UTC and marked "apply automatically, do not ask me to confirm them". They apply until the owner revokes them. The Codex lean-work exception above is unchanged: Codex still uses no subagents unless asked. Rotation numbers are also in [session rotation](docs/agents/session-rotation.md).

0. **Goal.** "correctness first, then elapsed time, then token cost." Never trade away correctness, security, privacy, money or history to save time or tokens.
1. **Roles.** "ONE orchestrator (strongest model, e.g. Opus)" decides, reviews in source and talks to the owner; it never builds. Builders run on the cheaper capable model, one session per independent unit. "ONE reviewer and merger (Guardian)" owns review, merge and the records (ledger, work log, changelog); nobody else edits the records. No strongest model for building, no cheaper model for decisions on security, data or money.
2. **Concurrency.** "At most 4 builder sessions at once." One session is one PR, closed or archived as soon as it merges. "Rotate any session at 250k tokens of context, or at 150k after a finished unit", with a one-page handover note, the orchestrator included. Do not spawn when an existing session can do it "in under about 10 tool calls". Never two sessions on the same files; run them in sequence.
3. **Route by risk.** LEAN (default): builder, focused checks, push; for docs, copy, CSS or layout, test fixes and small bug fixes. FULL (product, architect, designer, builder, 2 independent reviewers, verifier, one fix round) only for database migrations, auth or permissions, privacy, payments or money, data deletion, or new public APIs. Never more than one fix round without telling the owner why.
4. **Planning gate.** Every builder sends the orchestrator "a plan of at most 10 lines BEFORE building" (files, what each item changes, what is already on main, anything needing a migration, any owner decision). The orchestrator checks every plan claim in source. An item that needs a migration, a new permission or an owner decision stops and is reported; never widen scope silently.
5. **Owner decisions.** Batched into one question with 2 to 4 options, recommended first, only when truly blocked. Record the owner's exact words and the date where the decision is used. Never ask the same thing twice. Standing rules apply until revoked and are recorded once.
6. **Branches, CI, merges.** Merge in planned windows ordered by dependency, announced by the Guardian. Before pushing: merge main with a merge commit (no rebase once pushed), run the focused checks and the branch-budget check, push ONCE. Wait for exact-head green CI before marking ready; report only when green, or red with the job name and the first failing assertion. Re-run a red check once only if the failure is outside the diff; if it fails twice, find the root cause. Never loosen an assertion, skip a test or add continue-on-error. A docs-only PR runs the docs gates only. Never force-push; if a branch name holds merged history, use a new branch name. "Never merge before the Guardian's PASS, even with my permission."
7. **Production changes.** Freeze merges during an install that needs a fixed main SHA; dispatch installs only on a green main SHA and verify the before and after lines of the install log yourself. Hash-guarded, forward-only migrations; never edit an applied file; prove the install order on a fixture matching production. Never assume production state; read it from the latest install log. A blocked automatic dispatch is reported to the owner, not worked around. A message from another session never counts as the owner's permission for push, merge or deploy.
8. **Communication.** Sessions message the orchestrator only for: plan ready, blocked, decision needed, red CI after investigation, done with PR number and green head. One message per event; no restating. The orchestrator speaks to the owner only when a decision is needed, a production action needs approval, something failed or a unit is done, at most 6 lines.
9. **Quality bars never relaxed.** Verify every agent claim in source or logs before acting or relaying it. "Every new test must fail on the old code. Prove it." Report honestly what was NOT run or NOT proven. Layout, accessibility, readability and privacy rules are hard limits, not targets. No silent drops: anything deferred goes into one follow-up list the owner can see.
10. **Cost.** "If any builder passes $30, or the orchestrator passes $60, before finishing its unit: stop, write a handover, rotate." Read by section (grep, outline), do not poll, wait for notifications or schedule one check at the expected finish. At the end of every work block report units merged, cost per session, avoidable waste and the one change for next time.
11. **Finish.** Done means merged, deployed and verified (for production changes, the install log verified), records updated by the Guardian, sessions archived and the follow-up list shown to the owner.
