# Part 08 requirement baseline

The implementation plan defines client and institutional delivery. Its requirements inherit the full architecture canvas, public-experience institutional programme flow and constitution's proof hierarchy. Part 07 is deployed; the owner explicitly deferred its production commercial write acceptance. That remains recorded in PR #22 and does not become a passed check here.

| Requirement                                 | Implementation contract                                                                                                                                   | Required evidence                                                                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Scoped client mission view                  | Human-approved mission publications, purpose-bound expiring/revocable links, no tenant membership or private operator data                                | Unrelated mission/tenant denial, expired/revoked link denial, HTTP scanner denial and mobile client journey                 |
| Brief, itinerary, progress and next actions | Reviewed client copy; approved meeting subset and schedule version; canonical state and clear update timestamps                                           | Schedule changes cannot disclose unapproved locations; no raw intake/contact/negotiation leakage                            |
| Evidence request flow                       | Owned, dated requests, immutable self-declared replies, explicit fulfilment/cancellation without verification                                             | Replay/conflicting reply, closed request, cross-mission and revoked capability checks                                       |
| Institutional CSV/Excel intake              | Bounded CSV and XLSX parsing; preview with every row result; explicit confirmation; canonical mission-service command                                     | Formula/macro/XXE/archive denial, malformed/blank/duplicate rows, changed-reference conflicts, retry and atomic rollback    |
| Cohort dashboard                            | Approved publication scope, participating-company denominator, qualified counterparties, held meetings, opportunity/RFQ/sample/proposal/contract outcomes | Reconciliation against Ops, unapproved participant exclusion, complete paging and mixed currencies                          |
| Purpose-scoped CSV/PDF exports              | Exact dashboard DTO, neutralized formulas, paginated font-encoded PDF, immutable content digest and audit/outbox                                          | Export permission/redaction tests, retry equality, generated artifact inspection and browser download                       |
| External API restraint                      | Internal application contracts only; no speculative partner API or credentials                                                                            | Existing routes and identity boundaries remain intact                                                                       |
| Safe release                                | Forward migrations, original-record preservation, normal PR/CI/preview gates, feature rollback and live verification within current authorization         | Fresh and populated upgrade; real restricted-role RLS tests; complete browser checks; exact deployment evidence and cleanup |

Programme imports continue to require invented example.invalid participant addresses. Client evidence responses remain self-declarations. Files use existing evidence collection and scanning controls. No AI, payout, real outreach or customer signup is activated by Part 08. D01 to D06, D08 and D09 remain tracked in the deferred controls register. Human admin access created at the owner's request remains intact and is not reused as an automated test identity.
