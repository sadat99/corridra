# Part 06 implementation and release status

Controlled introductions, minimal no-account buyer responses, canonical meeting operations, owned follow-up and durable synthetic outbox dispatch are implemented on `feat/part-06-controlled-access`. [The requirements map](part-06-scope.md) records the vision and acceptance scope; [ADR-018](../adr/0018-controlled-introductions-and-meeting-truth.md) explains the security and orchestration contracts; [the runbook](../runbooks/part-06-access-and-meetings.md) describes the complete operator, buyer and recovery flows.

New migrations 0009 and 0010 are additive. Owner/admin policy/template approval requires fresh MFA. Every introduction retains its approved versions and human author. Current jurisdiction/channel policy, source/contact validity, relationship access, mission state and recipient opt-outs are enforced in PostgreSQL before delivery. Links use 256-bit capabilities in fragments, SHA-256 storage, strict minimal reads, shared budgets, expiry and immediate revocation. GET/HEAD do not decide. Concurrent repetitions produce one response/event, and a changed replay fails.

Meeting commands preserve PROPOSED, ACCEPTED, SCHEDULED, HELD, DECLINED, CANCELLED, NO_SHOW and RESCHEDULE_REQUIRED. Acceptance retains its response or observation. Explicit offsets and IANA timezone/local-time agreement reject DST gaps and inconsistent schedules. Held outcomes atomically require an observed outcome and owned/deadlined follow-up. Immutable command history retains earlier schedules. Mission progression extends through outreach, meetings and follow-up; commercial opportunities/cash remain Part 07.

Workflow 5.2.0 runs identifier-only jobs through the transactional outbox adapter. PostgreSQL leases, bounded attempts, receipts and checkpoints make duplicate starts and ambiguous acknowledgements safe. Dead-letter retry requires an explicit reason and retains history. Operators explicitly start/recover pending jobs. Introductions and dispatch default off. Compatible patched devalue/nanoid versions resolve the Workflow transitive advisories found during validation.

All 143 local tests passed: 7 document, 7 infrastructure, 80 real PostgreSQL integration, 46 public browser and 3 protected browser tests. Formatting, lint, typecheck, production build and the production dependency audit passed. [The dated validation record](part-06-validation.json) separates that local proof from PR CI and deployment. Fresh ten-migration setup and a populated Part 05 upgrade passed. The protected browser test used an actual password/TOTP session and the real local Workflow runtime, then exercised a mobile no-account buyer response, meeting acceptance/scheduling/held outcome, persisted follow-up, opt-out and sign-out denial. No remote CI, cloud migration, production alias/SHA or cloud Workflow execution is claimed by that local record. The existing production system is unchanged by this implementation branch.

EMAIL is blocked by the current runtime and SQL. Synthetic receipts send no email; manual receipts record human handoff only. Real outreach requires explicit email permission, reviewed jurisdiction/legal basis, sender-domain readiness, provider regional/data review and applicable D08 controls. Existing scanner/account/retention deferrals remain open. An authorized production release must follow the runbook, verify exact deployment/migration evidence and exercise the new buyer route on that deployment. Rollback disables introductions/dispatch, revokes affected links and keeps immutable history and additive schema.
