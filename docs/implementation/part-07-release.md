# Part 07 implementation and release status

Commercial follow-through is implemented through [PR #22](https://github.com/sadat99/corridra/pull/22). Its release evidence records the current exact revision, CI, preview, production migration, functional acceptance and cleanup status. The production entry point is [corridra.vercel.app](https://corridra.vercel.app). [The requirement baseline](part-07-scope.md), [ADR-021](../adr/0021-commercial-funnel-cash-and-outcome-projections.md) and [runbook](../runbooks/part-07-commercial-followthrough.md) define scope, accounting authority, complete operator operations and rollback.

The module links held meetings to owned opportunities and immutable RFQ/sample/proposal/commitment/contract/invoice/cash/recurrence records. Accounting confirmation is a separate fresh-MFA owner/admin action. SQL preserves tenant/purpose/country and relationship permissions, immutable financial history, parent currency, invoice caps, confirmed-payment limits and explicit compensations. Observed contracts, invoices, reported receipts and confirmed cash remain distinct.

Additive migrations 0011 to 0013 introduce typed canonical views, currency registry, ordinary-event outcome snapshots and versioned relational projections. Reports show actor-visible activity, access, historical funnel stages, currency-specific financial totals and attribution limits. Commands default off. Replay retains original events and records every rebuild's reason and audit entry.

[The validation record](part-07-validation.json) preserves local and isolated preview evidence. The complete local release gates passed: 7 document integrity tests, 7 infrastructure tests, 108 real PostgreSQL integration tests, 46 public browser tests and 4 protected browser tests, plus format, lint, typecheck, build and the production dependency audit. The protected journey covers actual password/TOTP, intake, buyer response, held meeting, confirmed cash, recurrence, compensation, deterministic replay, mobile accessibility and stale-session denial. Populated upgrade preserves previous mission, meeting, identity, membership, event and outbox records. Cloud release acceptance is tracked in the PR release evidence; a READY preview alone is not production acceptance. Customer signup remains deferred under D09; the other recorded customer-data, outreach, scanner, retention and pilot/legal boundaries remain in force.
