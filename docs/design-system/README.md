## 2. What AC/1 decides (summary, not a replacement)

- **Brand lock:** Midnight Navy `#142438`, International Cobalt `#2856C5`, Porcelain `#F6F8FB`, Copper `#BF7548`, Ink `#18283C`. Replaces ivory, forest green and gold.
- **One foundation, four compositions:** Meridian (customer and mission shell), SourceLedger (comparison and evidence), Encounter (delegations and meetings), Commerce Atelier (public and discovery), Signal Desk (staff, founder, governance). Not five themes. Composition is chosen by task and information type, never by role, country or taste.
- **Semantic separation:** cobalt is the action, selected and focus colour. Navy is chrome and the dark contrast surface. Copper is editorial ornament only, never a warning and never small text. Status colours are independent of brand.
- **Nothing functional changes:** destinations, roles, deep links, the 18 operator section IDs, drafts, evidence, trust labels, money and history are preserved. A role governs access, not a visual brand.
- **Human gate:** an agent cannot pass art direction. Each reference screen and each page family needs a named human reviewer.

## 7a. Implementation notes (23 October 2026)

- **Audit method for signed-in screens** is in [known issues KI-16](../v3/KNOWN_ISSUES.md): a local copy of the operator specs with an axe subclass that measures action geometry, a short-fill measure and a real-frame mode that mounts components under `main.ux-customer`. Use it before restyling any signed-in screen; the static UX gate (`pnpm test:ux`) only sees the 42 public routes.
- **Operator home bento kept (23 October):** the tool index (one navy featured tile and four cards) and the phone area bar are featured compositions that the local audit measures as uneven. A uniform grid looked worse (evidence: `evidence/signal-tool-index/bento-vs-uniform-1440.png`) and was reverted; the audit flag is documented in KI-16 as not a defect.
- **Selector pitfalls found**: the customer kit zeroes heading margins in every section (`.ux-customer :is(section, article, aside, details):not(.guide-band) h3`), so a rule that adds heading spacing needs equal or higher specificity; `.ux-customer button:not([class])` styles every class-less button, so tabs must be excluded; legacy `.operator-page .text-link { margin-right: 15px }` shortens controls that stretch in a grid, so reset it inside the container.
- **Evidence for a package** is stored under `docs/design-system/evidence/<package>/before` and `after` (example: `ac1-08-atelier`, four pages at 320, 390, 768 and 1440 px, before taken from the merge base).
- **Owner decision 23 October (chat)**: there are no live users to protect, so broad presentation changes are allowed. Closed gates, permission checks, money and data semantics, and the parity checks still apply.

## 8. UX quality gate (`pnpm test:ux`)

`tests/ux/ux-gate.spec.ts` with `playwright.ux.config.ts` loads every static route under `apps/web/app` (dynamic `[segment]` routes are skipped) at 320, 390, 768, 1024, 1440 and 1920 px with reduced motion, and counts per route:

| Check            | Rule                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `overflow`       | No page-wide horizontal scroll                                                                                                               |
| `smallTargets`   | Interactive targets at least 44 px up to 768 px wide and 24 px above; inline links in running text and visually hidden skip links are exempt |
| `invisibleFocus` | Each of the first 30 Tab stops shows an outline or ring                                                                                      |
| `pillControls`   | No capsule-shaped buttons or links (capsules are for status badges)                                                                          |
| `crowdedRegions` | No more than one primary action per section, form, aside or nav                                                                              |
| `tinyText`       | No visible text under 12 px                                                                                                                  |
| `axe:<rule>`     | axe-core WCAG 2.0, 2.1 and 2.2 A and AA violations by node                                                                                   |
| `unavailable`    | Route answered 4xx or 5xx (expected for routes whose module is off)                                                                          |

The run fails when any count rises above `tests/ux/ux-baseline.json`, and when a new route has no baseline entry (new routes start clean). Lower the baseline in the same change that fixes debt; never raise it. `UX_UPDATE_BASELINE=1` records counts and is only for reviewed debt. The report and 390/1440 screenshots go to `work/ux-gate/` locally and to the `ux-gate-report` CI artifact.

First baseline (22 Oct 2026, 39 routes): every check is 0 except `/workspace` `crowdedRegions` 6 (two primary actions, "Open my account" and "Team sign-in", in one section; left for the Meridian reference package) and `/account/service-requests/new` `unavailable` 6 (module off). Raising the wordmark link to 44 px removed the only real small-target finding. Signed-in screens are not covered here; the protected operator suite covers them. No automated gate replaces task tests with real users.

Routes: every static `page.tsx` route plus the corridor pages that `generateStaticParams()` renders from `content/corridors.ts` (42 routes). A redirect is recorded as `redirectsTo:<path>`; a new or changed redirect fails the gate like any other count.
