# UX update: customer data inventory (Lane 1, 24 October 2026)

Status: dated inventory, read from the code at `main` `48a4ed2` and re-checked before each lane that relies on it. It lists what a signed-in customer can read today, so that Your Move, the Room, the Road and All tools are built only from states the system already holds. It changes nothing. Where this inventory differs from the UX plan, the inventory wins and the plan is corrected in the ADR that follows (see section 8).

## 1. Facts that apply everywhere

- **Every customer module is off by default.** A module is on only when its setting is exactly `true`, and most depend on `customerWorkspacesEnabled`. A closed gate renders an "unavailable" page and the API answers 503. Billing, programmes, participants, saved missions (which also needs `CORRIDRA_DELIVERY_ENABLED`), companies, decisions and member roles each have their own gate.
- **Every customer page** reads the session, sends a signed-out visitor to `/signin` and an unverified one to `/verify-email`. Customer APIs read the headers `x-corridra-customer-subject` and `x-corridra-customer-issuer`, and the database checks the session again.
- **Workspace role** is owner, admin or member. The database helper `customer_private.organisation_profile_role` answers `writer` (owner or admin) or `reader` (member). Members can read but not act on service requests, company links or billing.
- **Data mode:** every payload carries `synthetic`. Sample data and real data are never mixed on one screen.
- **There is no account-wide "needs your attention" feed.** Drafts and service requests are listed per workspace, and there is no endpoint that joins them. A front door has to loop over the person's workspaces and read each source it uses.

## 3. The account home today

`/account` has four views chosen by `?view=`: `home`, `work`, `results`, `more`. Anything else is `home`.

- **home:** the saved-request notice, a Next Step card ("Start a request", or "Plan a mission" when requests are not on), and links under "Have something to open?".
- **work:** "Manage your work" links, the workspace list, delegation registrations and the request list.
- **results:** assigned missions, saved reports, approved companies and the paste-a-link box.
- **more:** account details, sign-out, the team invitation hint and the other ways in.

`hash-redirect.tsx` maps the old hashes (`#my-work`, `#customer-workspaces`, `#customer-requests` to `work`; `#results`, `#customer-missions`, `#saved-commercial-missions` to `results`; `#more` to `more`) onto `?view=`. Both must keep working.

The sign-in return rule `accountReturnTo` (`apps/web/lib/account-return.ts`) accepts exactly `/plan` and nothing else; everything falls back to `/account`. It is navigation only. An email link therefore loses its destination at sign-in until the rule is extended to a short allow-list of exact internal paths (Lane 7).

- No production route imports `apps/web/components/mr` (a test now enforces it).
- `owner-switches.ts` accepts `planned` entries without a state source (the resolver returns "Planned, not built yet").

## 7. Not found

- No aggregation endpoint for drafts or service requests across workspaces.
- No retention rule for server-side drafts.
- No customer-facing "needs more evidence" state on service requests or reports beyond a company link in `needs_evidence` and a delivery evidence request in status OPEN.

## 8. Facts that correct the UX plan

Found while reading the code for Lane 3 and later lanes. The ADRs state the corrected design.

- **Replies are not versioned.** `app.recipient_detail_response` holds one immutable row per link (`UNIQUE(tenant_id, link_id)`, rewrite rejected). There is no revision, status or review column.
- **There is no review action today.** "Counterparty declarations awaiting review" is a read-only list. A reply reaches a customer only through a manual path: the Corridra team re-enters the terms as a mission quotation, approves a publication and shares it.
- **The comparison engine does not flag warranty, installation, training or spares.** It flags twelve terms as missing: specification, quantity, unit, unit price, lead time, valid until, trade term, shipping, payment terms, tooling, set-up and packaging. The seven-field reply form can therefore never reach "Comparable on supplied terms". The database function already accepts eighteen term keys, so the Reply Page asks for the terms the engine needs.
- **Per-recipient language does not exist.** Language is browser-local, and `/buyer` copy is fixed English.
- **Mission mail accepts one kind.** The queue constraint allows `request-received` and `your-move`, but `enqueue_mission_mail` raises for anything except `request-received`. Messages 4, 5, 6 and mission complete need a new queue.
- **ADR numbers 0062 to 0065 are taken** (billing and report access). The UX ADRs start at 0066.
