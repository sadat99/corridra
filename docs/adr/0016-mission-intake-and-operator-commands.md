# ADR-016: Mission intake and operator commands

Status: Part 04 implementation. Release evidence is recorded separately.

The owner requested Part 04 after the Part 03 production-domain rollout. Continue using the existing Frankfurt synthetic database and private evidence adapters. Scanner and account-control deferrals remain in ADR-015 and the deferred controls register. They do not establish customer-data readiness.

Anonymous intake is a narrowly scoped database capability, not a tenant session or a new identity role. An offline administrator configures one synthetic destination, its active owner and a distinct service principal. Runtime cannot read or change that destination, choose a tenant/actor, insert mission rows directly or obtain broader permissions. Fixed-search-path functions accept validated test briefs and return only a mission receipt. The service actor identifies ingress automation; it does not impersonate the submitter or assert MFA.

The five-step form preserves drafts in tab-scoped session storage for up to 24 hours. Server validation is authoritative. Test email addresses must end in @example.invalid. Optional public website/catalogue links are recorded without fetching them. Phone and anonymous document uploads are deferred because they are unnecessary for this test intake; authenticated evidence requests remain available through Part 03. The original brief, notice version, acknowledgement timestamp, observation, self-declared status and 30-day retention window are retained. Automatic deletion remains open work and is disclosed.

One transaction creates the mission, intake, objective, participant, original market, timezone-aware visit window and original commercial intent. A transaction lock serializes retry-key and 24-hour content deduplication across replicas. Retry keys cannot be reused with changed content. A content duplicate with a different key returns no receipt or mission identifier. Keyed hashes avoid storing raw deduplication/contact identifiers in the abuse ledger. Shared PostgreSQL budgets limit six requests per client and sixty globally per hour. The global budget applies even when the platform address is absent or unreliable.

Receipts are opaque 256-bit capabilities sent in POST bodies, not URLs. The database stores only their hashes. Read access returns state and operator-authored replies, without the original brief or contact details, and expires with intake retention. GET requests cannot submit a brief, write a reply or change a mission. Receipt delivery is a working browser response channel. Email delivery and a monitored privacy contact are not implemented or invented.

Owners, admins and operators manage missions under the existing session/MFA, purpose, classification, country and tenant policies. Reviewers and viewers can read their allowed queue but cannot change it. Qualifying a draft creates a self-declaration source and claim with the original intake notice and observation date; qualification never verifies the claim. All changes require an active operator owner, next action, due timestamp, reason, structured market and target profile. A row lock and expected version prevent lost updates. Idempotent command IDs and reply IDs support retry after a lost response.

The full canonical state vocabulary is reserved. This packet implements DRAFT to QUALIFICATION to ACTIVE, ON_HOLD with restoration of its prior state, and CANCELLED. Downstream targeting, outreach, meetings and commercial progression require their later parts. SQL guards independently reject unsupported transitions, identity/version changes, invalid owners and missing qualification records. Mutable commands emit a minimal, versioned event, audit entry, outbox message and delivery checkpoint atomically. Reasons, complete action-detail snapshots, version-ordered target-profile history and replies remain append-only; contact text is absent from event payloads.

The production domain exposes a functional test intake and protected Ops Home. Real customer intake requires the responsible legal entity, approved privacy notice/contact, working customer response delivery and retention/readiness gates. Until those details are supplied and implemented, use only invented records. Public copy states this limit explicitly. Original supplied documents remain unchanged.

Offline intake-destination configuration emits immutable security events. Target profile versions follow the locked mission aggregate, so transaction start times cannot select an older profile after a newer action commits.
