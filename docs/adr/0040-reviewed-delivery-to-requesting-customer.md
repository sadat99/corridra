# ADR-040: Reviewed mission delivery to the requesting customer

Status: bounded local implementation and acceptance;full exact-head CI/release pending. V3-06-004 remains PARTIAL;actual managed-provider acceptance NOT VERIFIED.

The customer already has a creator-owned request binding to its canonical V2 mission. Approved commercial reports currently need a separate private invitation to be discovered and saved. Reuse the canonical mission,original reviewed CLIENT_PROGRESS publication/link,and existing customer save/read/reply/companies/decision engines. Do not create another mission system,customer staff identity or organisation-wide report authority.

An owner/admin with fresh MFA explicitly binds their own existing active client report link to the original request on the exact same tenant and mission. The new immutable assignment contains the staff actor,opaque original request ID and original link ID;it does not copy reports,contacts or original evidence. New table/tenant RLS/guard and original atomic event/audit/outbox only. No old function,policy,signature,history or money rewrite. Binding a link does not activate outreach or email. Original link/publication revocation and expiry remain authoritative;no new independent revocation path can leave a saved report alive.

A fresh admitted request creator discovers only their own approved assignments in the account. Workspace owners,members,organisers and another customer inherit none. No matching by email,company name or guessed mission IDs. List exposes only opaque assignment/request IDs,approved title and current availability/expiry;no bearer token/hash,provider subject,staff principal,raw global organisation ID or private request source. Expired/revoked/unavailable items expose no stale title. Pagination is bounded and explicit.

Saving/opening requires the customer's explicit acknowledgement and a fresh proof. A new narrow port resolves only that creator's assignment,then calls the existing customer.save_mission_invitation using the protected original digest inside SQL. The old bookmark idempotency/removal/access/report/reply behavior remains unchanged. The returned private resource opens the existing commercial report route. No token is sent to the browser and no staff session or customer proof is forged. Read/accept must recheck proof,request retention/revocation and original link after waits. Staff approval rechecks wall-clock MFA/session and scope before and after original events,with atomic rollback.

Separately optional module and protected receipt;default-off synthetic/nonproduction flag plus existing private request/workspace/saved/delivery gates. No cloud module installation,provider/admission/intake/exposure or D01-D06/D08 change. Actual managed-provider acceptance remains NOT VERIFIED. Rollback disables exposure or deploys compatible source;retain additive assignment/audit/history and existing bookmarks.

Required acceptance:populated prior functions/ACLs/RLS/rows/receipts unchanged;owner/admin positive;operator/reviewer/viewer/customer/tenant/private SQL denials;real other-mission/link/publisher rejection;creator-only discovery and explicit save into unchanged report/read/reply flow;no contacts/token/hash/subject;expiry/revocation/removal,exact retries/concurrency/conflicts,postwait MFA/proof,atomic event rollback. Actual UI must cover loading/empty/unavailable/denied/malformed/retry/hide/account/expiry,keyboard/WCAG/four widths and current compiled closed routes. Full exact-head CI and matching merged READY deployment precede source release. Full customer canonical authoring and organisation ownership remain unfinished.

Request retention/revocation governs discovery and new acknowledgement. An already accepted client report is an independently reviewed permission under the original link/publication contract;request revocation alone does not silently rewrite that grant. To withdraw the delivered report,the original canonical client link/publication revocation closes both account delivery and saved report access. The UI distinguishes unavailable delivery from independently saved reports. This preserves separate authorities rather than merging them for navigation convenience.
