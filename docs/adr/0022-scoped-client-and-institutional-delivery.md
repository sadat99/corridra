# ADR-022: Scoped client and institutional delivery

Status: accepted for Part 08 implementation. Release evidence is recorded separately.

Client progress and institutional reports use explicit, human-approved delivery scopes. Existing operator password/TOTP and Neon Auth customer accounts remain separate under ADR-020. Customer signup stays deferred. An approved, expiring private link can deliver a mission or programme without creating an operator membership or enabling signup. Its token travels in a URL fragment and POST body, and PostgreSQL retains only its digest. A link grants one declared audience and purpose, optional reporting/export permission, and an exact set of approved mission publications. GET/HEAD never disclose private data or write a response. Revocation, expiry, publisher access loss and retention take precedence over a replay.

A publication contains reviewed client copy and an explicit subset of meetings and opportunities. The server never copies raw intake notes, private contacts, negotiation text, accounting bases, record references or margins into a client response. Meeting schedules carry their approved version; a later schedule change requires an updated itinerary. Canonical mission/meeting state and approved opportunity outcomes remain live. Contract, invoice and confirmed cash are distinct, grouped by currency; repeat cash is already within confirmed cash. A shared canonical aggregation function serves Ops and delivery reports. No FX or causal attribution is invented.

Evidence requests have an owner, deadline, instructions and immutable self-declared client responses. Completing a request records fulfilment, not verification. Client replies provide a textual declaration; supporting files continue through the existing controlled evidence collection, quarantine and review workflow. The new form promises a response, not an unrestricted document upload. Neither a link nor a response verifies a claim.

Operators prepare institutional CSV/XLSX intake on behalf of a programme. Parsing is bounded; unsupported workbooks, macros, formulas, external relationships, XML entities and dangerous archive expansion are rejected. Every logical row has a visible result, including blank and duplicate rows. Invalid or conflicting rows block confirmation. Confirmation states the accepted, duplicate and blank counts and records the operator's explicit acknowledgement. References are unique within a programme. The same reference and brief returns the original mission; changed content conflicts. Batch retry is actor/request-bound and atomic. Canonical mission creation belongs to the mission service and composes within the import transaction; delivery never updates another domain's tables directly.

Exports use an explicit reporting purpose and the same approved DTO as the dashboard. CSV cells neutralize formula execution, including leading whitespace and control characters. PDF text is encoded through an embedded font and paginated. Both formats contain a generation time, scope/version, denominators and attribution limits. A successful generation atomically records its content digest, audit/domain event and outbox; download retries reuse the same result without duplicate events. No unauthenticated general query, partner API or integration credential is introduced without a validated integration requirement.

The application feature switch permits deployment rollback without deleting imports or publications. SQL and services independently enforce tenant/relationship scope and fresh MFA for sharing. Existing synthetic data, scanner, legal, retention and signup boundaries remain active. Original source documents and historical migrations are immutable. Forward migrations introduce the mission import command, shared outcome aggregation and delivery tables/functions; populated upgrades must preserve old rows and original owner/admin access.
