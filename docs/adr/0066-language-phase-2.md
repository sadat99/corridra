# ADR-066: Language, phase 2 (what the language foundation does, and what is added)

Status: accepted by owner delegation, 24 October 2026 (see the execution record in [the UX plan](../product/ux-update-plan-corrected-2026-10-24.md)). Written to match what PR171 and PR174 built, plus the small additions below. Default off: with `CORRIDRA_LANGUAGES_REVIEWED` and `CORRIDRA_LANGUAGES_PREVIEW` unset only English is offered, the chip does not render and no visitor sees a change.

## Context

PR171 and PR174 added the language chip, the message module and the provider ([proposal](../product/language-switcher-proposal.md)). No ADR recorded the decisions behind them. The UX update adds new screens (Your Move, the Room, the Road, quote cards, a first question) that must be written for translation from the start, and Bangla in particular needs more than translated words: how it is set in type.

## What the foundation does (recorded as built)

| Topic                       | Decision                                                                                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Where the choice lives      | In this browser (`localStorage`, key `corridra.language`). Where storage is blocked it is kept for the visit. Another tab's change clears the in-memory choice so tabs agree.                                 |
| What the server knows       | Nothing. No cookie, no header, no account field. Pages are built in English and stay static on the CDN.                                                                                                       |
| First visit                 | The browser's own language, if that language is offered. Otherwise English.                                                                                                                                   |
| Release                     | A language is offered to the public only when it is named in `CORRIDRA_LANGUAGES_REVIEWED`, which the owner sets after a native reviewer is recorded ([review record](../product/language-review-record.md)). |
| Drafts                      | `CORRIDRA_LANGUAGES_PREVIEW=true` shows every unreviewed language, labelled "draft", for the owner to read. Never set for the public.                                                                         |
| Page language and direction | Set on `<html>` after load. A main region still in English says `lang="en" dir="ltr"` itself, so only translated chrome follows the choice.                                                                   |
| Right to left               | Arabic mirrors by logical properties (`inline-start`, `inset-inline-end`). Only directional icons flip.                                                                                                       |
| Numerals                    | `displayDate` and `displayMoney` take the language tag. Amounts keep every digit and the original currency in every language. Whether Bangla or Arabic shows its own numerals is a reviewer decision (below). |
| Fallback                    | A missing or empty entry shows English. An entry is never blank.                                                                                                                                              |
| Not done on purpose         | No language in the address, no server-side language, no translation of company names, quotations or original text.                                                                                            |

## What this phase adds

1. **Words for the teaching layer.** 46 message keys (`mr.*`) in English and as drafts in Bangla, Chinese, Spanish and Arabic: the Road steps and states, the holders, the Move verbs and the sentence pattern, the quote card, the example and sample labels. The components take them through `mrLabelsFor(locale)` (and `useMrLabels()` in a client component); with no labels passed they render exactly the English they rendered before. Words for Your Move, the Room and the first question are added with those screens, so no key exists without a user.
2. **A sentence pattern, not a sentence.** `{verb} {object}` for English, Spanish, Chinese and Arabic; `{object} {verb}` for Bangla, because the verb comes last. A translator may reorder but must keep both placeholders (a test checks it).
3. **A test tying the language list to the formatters.** Every language in the chip is accepted by `displayDate` and `displayMoney`, and the digits of an amount read back identical in each language's numerals. A language cannot be added to the chip that the formatters reject.
4. **A pure move of the chip styles.** The language chip rules moved out of `apps/web/app/globals.css` into `apps/web/components/language-switcher.css`, imported by the chip. Not one rule changed (the compiled rules were compared, 11 of 11 identical, and the new sheet loads after the global one as before). This is the only edit to the global file in the whole UX update.
5. **No letter-spacing for scripts that join letters.** `apps/web/components/language-scripts.css`: when the page language is Bangla or Arabic, text in that language is not letter-spaced. The product sets many small labels in spaced capitals, right for Latin and wrong here (it breaks Bengali conjuncts and Arabic joins). The rule matches nothing while English is chosen, and never a main region still written in English.
6. **Evidence.** Bangla in a Road, a Move card, a quote card and a table at 390 and 1440 pixels: `docs/design-system/evidence/language-phase2/`.

## Localization standard for every string

Scannable at a glance. Buttons one to three words. Bangla in a modern corporate register with technology words written in Bengali script as people say them; B2B and RFQ stay as professionals say them. Words with legal or commercial weight are translated for exact meaning. The five trust names (Self-declared, Documented, Corridra-checked, Official source, Signed) are never weakened and are not translated in this phase (they appear in English beside translated labels in the screenshots; a reviewer decides). Figures of speech (Move, Road, Follow through) are translated by meaning, not word for word. No dashes used as punctuation in any language.

## Rollback

Delete `language-scripts.css` and its import, restore the chip rules into the global file, and remove the `mr.*` keys. The previous behaviour is unchanged because nothing mounts the teaching layer until Lane 4 and 5.

## Required acceptance

With both language settings unset the rendered page is as it was (English only, no chip). `tests/integration/language-phase2.test.ts` and `tests/integration/language-catalog.test.ts` pass; the specimen passes at 320, 390, 768 and 1440 pixels, including the letter-spacing check for Bengali and Arabic.

## Amendment: each translated page has its own release (30 October 2026)

Status: proposed with the request-form build. It becomes accepted when the owner accepts that pull request. It changes no contract above: pages stay static and English when built, the server reads no language, a language reaches the chip only through `CORRIDRA_LANGUAGES_REVIEWED`, and legal, consent and privacy text is never translated without a qualified reviewer.

### Context

This ADR releases a language through the chip and keeps every main region English. Since 25 October the home page's words follow the chosen language only for the languages named by `CORRIDRA_LANGUAGES_PAGES` (`apps/web/lib/i18n/pages.ts`); that setting was not recorded here. The owner reports it is on in production; no production state was inspected for this record. On 29 October the owner authorised translating the public request form `/plan` behind an independent, off-by-default `CORRIDRA_LANGUAGES_FORM` that must not inherit the home-page release. Legal, consent and privacy statements stay English, and the signed-in private request form, which mounts the same form component, stays English until its own phase. The first question inside the form keeps its own language behaviour, whatever the new setting says.

### Decisions

| Topic                   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One release per page    | A page on message files follows the chosen language only when its own setting names that language. Being offered in the chip is required but is never the release. `CORRIDRA_LANGUAGES_PAGES` releases the home page and `CORRIDRA_LANGUAGES_FORM` releases `/plan`. Both read the same way: unset or anything unrecognised releases none, `true` releases every language, a list such as `es,de` releases those. Neither implies the other. Each needs its own recorded review and a new deploy.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Where a release is read | On the server, when the page is built, by the page that owns it, and passed down as a value. The root layout's provider carries only the home-page release. `/plan` passes the form release to the region that renders the form, so the same form component mounted elsewhere (the signed-in private request form) stays English whatever the setting says.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Where the words live    | The form's words are their own files (`apps/web/lib/i18n/form-words/`), one module per language, keys under `form.`, outside the shared catalogue and outside `pageKeyPrefixes`, so no other page downloads them and the home-page release cannot reach them. English ships with the form. Another language's file is fetched only when that language is released, chosen and the form is on screen. The styles a translated form needs are in `apps/web/app/plan/form-languages.css`, loaded by `/plan` only and scoped to a translated main region (`.ux-intake-page:not(:lang(en))`), so they match nothing while the form is English. One class is new: `.lang-island` puts an English sentence on its own line inside a translated paragraph.                                                                                                                                                                                                                                                                                                                                                                                                               |
| What the server can see | Corridra stores and receives nothing about the choice: no cookie, header, account field or log line. The static host does see which language's words file a browser fetches, as it sees any static file. This is the one new signal; it is recorded here so it is a decision, not an accident. There is one words file per language, 5.1 to 5.9 KB gzip each on this build, and none is part of a page's first load. `tests/browser/plan-language-words.spec.ts` guards this: each language is one file of its own, `/plan` does not load any of them first, and neither `/` nor `/plan` fetches one while the setting is unset.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| What stays English      | Consent acknowledgements, notice link names, sentences on what a person agrees to, who can read or share their information, how long it is kept, and that nothing is an offer, plus the wording of the consent errors (see Messages). Data, codes, money, typed text, receipt and status codes, reply bodies and the brand stay as written. Inside a translated region each such part carries `lang="en" dir="ltr"`. These attributes are added only when the region is translated, so with the release off the page is unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Stored values           | The request is byte for byte the same in every language: English option values, job keys, country codes, the English market name and catalogue objective, and no language field. Translation happens only when text is shown. This is proved for German and Arabic against the real handlers and database in `tests/operator/z-ux02-intake.spec.ts` (the sample form) and `tests/operator/real-use-intake.spec.ts` (the real request, its account and its claim).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Messages                | Messages stay English in the form's state and are translated only when shown, by matching their exact English to the `form.message.*` keys. A `{name}` in a key matches a variable part, such as a currency code and its decimal places, or a schema minimum or maximum. Several problems joined into one message are read sentence by sentence. The keys cover the form's own messages, the request schemas including the schema library's own wording, the amount reader, the server handlers on the request path and the browser's own words for no connection. A consent error shows a translated instruction, then the English consent wording. A message with no translation is shown as written, marked English, after a translated opening line. `tests/integration/language-form.test.ts` fails when a mapped message no longer comes from its source (the browser's words cannot be checked this way), or when a message the schemas, the amount reader or the request-path handlers can send is not mapped. The only exceptions are messages that stay English on purpose and the test's list of messages the form never shows, each with its reason. |
| Fallback                | As before, an empty entry shows English. In addition, while a words file loads, and if it cannot be fetched, the form stays English and says so with `lang="en"`. The browser may keep a failed words file for the life of the page, so the next load of the page tries again. Choosing the language again in the same page is not promised to retry.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

### Consequences

- The owner has one more switch, shown on the Owner page (`apps/web/lib/owner-switches.ts`) with what visitors really get: Off, On, or the listed languages (for example "On for es, de").
- The form's words need their own row in the language review record, and that review is recorded before the switch is set.
- A later page (how it works, the signed-in screens) follows the same pattern: its own words module, its own release, its own review row.
- After load the form shows English for a moment while the chosen language's words arrive, as the chip already applies after load. Listen and the page language follow the region when it changes.
- Two page releases to reason about instead of one; the Owner page and the review record name each.
- Five rules in `apps/web/app/globals.css` now use logical sides (`border-inline-start`, `inset-inline-start` and `inset-inline-end`, `margin-inline-start`) so the draft notice, the journey bar line and the form's main button mirror in Arabic. In a left to right page they compute exactly as before. This is a further edit to the global file, after the chip move (item 4) and the Bengali font (question 1).

### Rejected options

1. Reuse `CORRIDRA_LANGUAGES_PAGES`. It is reported on in production, so unreviewed form words would go live, and the owner required independence.
2. Add the form words to the shared catalogue under a page prefix. Every page would download six languages of form words, and `localeFor` would tie the form to the home-page release.
3. Read the form release in the language provider. The signed-in private form renders the same component inside it and would be translated.
4. Render `/plan` per request with the language on the server. It gives up static pages (option C of the switcher proposal).
5. Put every released language in the page or its bundle. Every visitor of `/plan` would download every released language, most of them unused. Kept as the fallback if the owner rules out the static-host signal above.

### Rollback

Unset `CORRIDRA_LANGUAGES_FORM` and redeploy: `/plan` is English and the same as the PR 214 form at every step (`tests/operator/ux-plan-languages.spec.ts` checks this with the setting off). A code rollback reverts the build commits. No data, migration, event, permission or money record is involved.

### Required acceptance for this amendment

With `CORRIDRA_LANGUAGES_FORM` unset the request form is the PR 214 form. `tests/integration/language-form.test.ts`, `tests/browser/plan-language-words.spec.ts`, `tests/operator/ux-plan-languages.spec.ts`, `tests/operator/z-ux02-intake.spec.ts` and `tests/operator/real-use-intake.spec.ts` pass.
