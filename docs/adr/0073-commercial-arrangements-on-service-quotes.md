# ADR-073: Commercial arrangements on existing service quotes

Status: bounded implementation; controlled local acceptance only. Production installation, release checks and genuine customer acceptance remain separate.

The owner's 28 October 2026 directive requires bundled supply, separate fees, conditional commissions and expressly combined terms. Existing itemised service quotes already preserve versions, original currencies, cost exclusions, staff MFA, handling-team ownership and digest-pinned customer acceptance. Extend those records rather than create another financial ledger.

The optional `customer-commercial-arrangement` module attaches one immutable terms snapshot to a new service-quote version in the same transaction. It records the actual buyer, seller, manufacturer, service provider, supply invoice issuer, supply payment recipient, delivery and warranty responsibilities, and an expressly unagreed importer where applicable. Party names are contractual snapshots, not new company identities or independently verified facts. Original stated terms remain available.

The four arrangements reuse existing fixed service-fee components by position. Every positive service fee must be referenced exactly once. A bundled supply price is attributed to its actual seller and is kept outside Corridra service totals; the sourcing economics may be included in that seller's price. A success commission records payer, recipient, triggering event, original-currency base, integer basis-point rate, half-up rounding and required evidence. Hybrid terms state whether commission adds to or credits the fixed fee. Credits require the same original currency. Commission calculations are conditional estimates, never earned, invoiced, collected or paid amounts. No meeting or quote automatically establishes a sale. Corridra principal sales remain blocked pending separate legal and accounting approval.

Private acquisition cost, markup and relationship notes occupy a separate field in the restricted metadata record. Customer projections and customer fingerprints never include them. Only the current handling staff team with fresh MFA can retrieve that field. A 20% markup on acquisition cost 100 derives selling price 120; it does not establish a Corridra commission or earned revenue.

The new wrapper repeats the existing staff authority and handling-team check before replay, uses the existing command/request lock order, calls the original quoting command and adds metadata atomically. A database insert guard rejects attachment to an old, viewed or accepted quote, a foreign team or mismatched command. Changed terms under an old command conflict. Authority is checked again after locks, metadata triggers and private reads. The table is append-only, RLS-enabled and unavailable directly to runtime/authentication roles. Existing event/audit/outbox quote records remain the event chain; no quote text or private costs enter events.

Only two existing projection helpers are extended in an additive migration: quote JSON and its public fingerprint. Without metadata their output and digest remain unchanged, including the existing real/sample provenance helper. With metadata the full public terms join the digest, so the existing seen-before-accept check covers those exact terms. Service acceptance remains an order intent for the stated service totals. A supplier purchase, seller obligations, earned fees, invoice, collection and payment each retain their own authority and records.

The protected customer-module workflow uses `field_modules_action=commercial_arrangements` (or `both`), default `unchanged`, with explicit `apply=yes` and exact-head checks. It installs the existing real-use helper dependencies without enabling real admission. Application builds never install it. Before installation the old quote path remains usable and the staff screen accurately reports arrangement terms unavailable. No production installation or activation has been performed by this implementation.

Acceptance includes all four modes through restricted SQL/customer services, unchanged populated legacy quotes/digests, repeated installation, exact accepted totals, private-cost non-disclosure, wrong-digest denial, direct SQL validation, immutable history, changed-command and cross-workspace replay denial, and post-trigger MFA expiry with complete quote/event rollback. Browser acceptance exercises the staff form, the customer terms, original values, explicit exclusions and four widths. Full release gates and provider acceptance are recorded separately in the V3 ledger.

Rollback uses compatible source and the existing service-request switch. Keep additive metadata and migration history. Do not erase terms or revert the digest helper after accepted arrangement quotes exist; use a forward fix preserving the exact accepted public content.
