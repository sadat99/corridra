# ADR 029: Evidenced route readiness and observed operations

Status: revised V2 Part 5 implementation; release evidence is separate.

The existing PostgreSQL services, RLS, immutable events/outbox, financial ledger and identity boundaries remain authoritative. Global administration means controlled configuration across authorized workspaces, not cross-tenant access. Configuration writes retain owner-only application authority; operational/accounting observations require owner/admin and fresh MFA. Publication requires an independent authorized owner. An owner without a second authorized reviewer can prepare a proposal but cannot self-publish it.

Readiness is directional, mission-type-specific and pinned to an exact pack. Thirteen dimensions require named active owners and retained source evidence. Missing, expired, superseded or blocked evidence cannot approve a release. Only the external-dependencies dimension may be explicitly inapplicable. Approvals preserve exact observation IDs and require a different reviewer. The current schema permits UNPUBLISHED, SYNTHETIC_APPROVED and PAUSED, never a real/public activation. A technical pack status is not legal or operational clearance. A pause blocks new assignments for that service without rewriting old assignments or affecting other routes.

Reviewed configuration proposals preserve their base and exact proposed pack. Preview identifies changed fields and retained assignments; it is not validation of every external capability. Publication checks the current base, independent identity and existing pack validators in one transaction. Reversion publishes an independently reviewed new version using the previous desired configuration. Existing trusted configuration services remain compatibility entry points; they do not grant real/public launch approval. Registered template versions reuse the existing schemas and cannot install code or arbitrary rules.

Corridra earned fees/costs remain in service_ledger. Separate append-only service_document records distinguish Corridra invoices and collections from customer commercial_record amounts. Receipts require the original same-currency invoice, cannot overcollect, and compensate exactly. Invoice reversal requires receipt compensation first. Effort and customer/industry/acquisition/completeness observations preserve their sources and versions. Completeness is an attestation; later ledger activity invalidates the margin calculation until a new completeness review. Missing records do not imply zero. Currency is never mixed, customer trade is never fee revenue, and association is not causal attribution.

AI lifetime mission ceilings add a narrower bound to existing tenant/day, task and attempt limits. Reservations remain charged to the ceiling after failure or a crash; no automatic release assumes a provider did not incur cost. The exact budget version is pinned to an attempt. A zero, expired or exhausted configured ceiling preserves manual fallback. Provider invoices, infrastructure bills and real-model quality remain unavailable without their actual evidence. Existing registered prompt versions change only through the reviewed release process, not executable administrator text.

Recovery preserves existing Workflow identifiers, event/receipt truth and safe duplicate orchestration. The database owns leases, three-attempt limits and bounded exponential backoff. Cases name a scoped subject, owner, deadline and evidence-backed resolution; case resolution does not deliver messages, verify tasks, delete data or pay contributors. Privacy cases track DSAR, legal-hold and incident decisions through existing source-rights controls. No automatic destructive retention executor is enabled without an approved policy.

Environment-plan validation requires distinct projects, branches, database/auth hosts, storage and credential references. A valid metadata plan or a list of approval IDs cannot activate real data. Existing live synthetic missions and separately approved customer identity remain intact. No production account data is cloned into a preview or restore test.

The release may ship synthetic controls with external gates closed. GitHub settings that returned 403 are unverified; no paid entitlement or server-side protection is inferred. Validated local Semgrep rules and redacted Gitleaks supplement existing assurance without claiming CodeQL parity. D01–D06 and D08 close only with actual evidence, not this decision.
