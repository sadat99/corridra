## Status words

Every plan, scope packet, proposal and audit starts with a line `Document status: WORD.` under its title. The word means the same everywhere.

| Word           | Meaning                                                                                            | May an agent follow it as an instruction?          |
| -------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| CURRENT        | Governs today and is kept up to date.                                                              | Yes                                                |
| CURRENT, DATED | True on the date in the file (an audit or inventory). Re-check against code before quoting.        | As evidence only                                   |
| DONE           | Planned, built and merged. The text records what was planned. It is not a to-do list.              | No. Use it to understand why code looks as it does |
| PARTLY BUILT   | Some phases are built and merged, the rest are not. The file says which.                           | Only the phases it marks as open                   |
| WAITING OWNER  | Written but not approved or not started. Nothing in it is built unless it says so.                 | No, until the owner approves                       |
| HISTORICAL     | Superseded or finished long ago. Kept for context. Statuses, counts and next steps inside are old. | No                                                 |
| NOT VALID      | A later owner decision or ADR replaced it. Never act on it.                                        | No                                                 |
| FROZEN         | Exact source or evidence. Hash-checked. Never edit. Amend forward in a current document.           | Read only                                          |

Rules:

1. If two documents disagree, the one with the later date and the stronger word wins: CURRENT beats DONE, DONE beats HISTORICAL. The ledger beats everything on live state.
2. A `Status:` line inside an ADR describes the day it was written (for example "pending release"). The decision is in force unless the ADR table below says otherwise.
3. Built is not enabled, enabled is not approved, approved is not live. Every row below says only what is true of the code and records.
4. When you finish or replace a plan, change its status word in the same pull request and update this register.
